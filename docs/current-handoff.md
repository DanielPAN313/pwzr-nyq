更新时间：2026-07-23

## 当前结论

- 当前主线是微信小程序，主工程为 `miniprogram/`。
- 当前分支为 `feature-miniprogram-flow`。
- PRD 阶段按 `P0 → P1 → P2.5 → P2 → P3 → P4 → P5 → P6` 执行。
- P0、P1、P2.5、P2、P3、P4、P5、P6 均已实现；最终验收审计已修正信用边界、档案门槛、核销结算和场地统一问题，完整检查已通过。

- 本地后端默认 `http://localhost:4174`，所有新增请求均保留静默 fallback。

## 已完成阶段

- P0：身份选择登录、球员/场馆角色落盘、场馆权限守卫、技术错误清理。
- P1：首页、出勤榜、订场、球局卡、取消报名状态流转、消息结构。
- P2.5：球队列表、球队详情、创建球队、队内比赛和球队数据工具。
- P2：球员六维档案、擅长位置、雷达图/条形降级、他人评价和编辑冷却。
- P3：场馆首页数据、场馆发球局、智能分队结果页、扫码/手动码核销、补核销闭环、场馆设置。
- P4：综合分标准化、段位微调、蛇形分组、位置风险、近分交换、门将分配和平衡校验。
- P5：统一支付适配层、模拟支付、支付回调、标准状态、模拟退款、场馆处理和 48 小时自动退款。
- P6：球局详情/列表邀请按钮、三套分享文案、携带邀请人的分享路径和社交契约文档。
- 最终审计：信用分硬截断 `0-100`，报名门槛 60、发局门槛 80，爽约 `-15`，迟到 `-3/-5`，互评 `+1/-1`；散客报名前要求已提交球员档案；可见场地统一为卡子门足球场。

## P3 关键能力

- 场馆首页展示今日收入、今日订单、到场率、进行中球局和待补核销数量。
- 场馆可发布散客局或赛事局；已有报名时仅允许直接修改备注。
- 场馆取消球局会通知报名用户，并把关联订单转为全额模拟退款。
- 核销支持扫码和 6 位数字码，时间窗为开场前 30 分钟至开场后 30 分钟，连续输错 3 次锁定。
- 用户订单页可申请补核销，场馆按订单号或手机号查询并确认；确认后信用分 `+2`。
- 场馆设置包含场地、价格、可订时段、临时闭场和收款配置预留，不包含员工账号。

## 自动检查

运行：

```bash
npm run check
```

通过时运行时检查应显示 29 个页面，并覆盖 P5 支付、P4 分队和 P3 场馆流程。

## P4 关键能力

- 新增 CommonJS 模块 `miniprogram/utils/team-balance.js`。
- 未评分用户和缺失维度默认 50 分，兼容 5 分制综合分输入。
- 支持 5v5、7v7、8v8 的位置目标；有两名及以上门将时尽量两队各一名。
- 输出总分、分差、平衡度、位置风险和手动调整提示。
- 自动检查覆盖蛇形顺序、人数差、`< 15%`、门将分配和默认评分。

## P5 关键能力

- 新增 `utils/payment/index.js`、`mock.js`、`wechat.js` 和场馆商户配置预留。
- 页面不再直接调用 `wx.requestPayment`；开发阶段明确显示“模拟支付”。
- 新增 `pages/payment/callback`，当前共注册 29 个页面。
- 订单支持 `pending_pay → paid/offline_paid → pending_verify → verified` 标准状态映射。
- 用户可申请模拟退款，场馆可处理，48 小时未处理自动退款并发消息。

## P6 关键能力

- 散客局、赛事局、默认邀请三套文案由 `utils/share.js` 统一选择。
- 分享路径包含 `id` 和 `inviter`，详情页与球局卡片均可分享到好友/群。
- 球局列表和详情页均支持复制邀请路径。
- `docs/social-contract.md` 预留 `user_follows`、`social_messages`、`social_posts`，本阶段不创建社区数据表。
